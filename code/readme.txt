This folder contains all the code I used in the minecraft work.

Much of this code is focused on heuristically reconstructing block ids from the images, detecting errors in the heuristic outputs, and updating xmls with new ids in the right places. If the goal is to construct a dataset for annotation that has unambiguous id's which are consistent across different time steps of the task then most of it is not required. The point of this guide is to help isolate the parts that are useful so they can be cleanly incorporated into the existing wokflow for generating data for annotation.

-------
Step 1. Updating  the image generation engine. This code has some extra functionality which will be useful later on. The functionality is activated by setting certain member variables of the App class which will move it into a different mode of operation when generating the image. Here are the specifics: 
 - setting "force_letter_for_coord" makes it generate everything as usual, but a particular block at the given coordinates will always have the same (supplied) letter --> this was useful for cycling through letter candidates on a block for the heuristic
 - setting "outside_coord_to_letter" (to a dictionary) will ignore the block glyphs generated inside the App class and instead look them up in a dictionary --> this is useful if you don't want the App class to generate block ids but you want to supply them from the outside (where they were generated to be consistent)
 - setting dont_ignore_block will draw only the given block and nothing else (no floor, axes, or other blocks) --> useful for determining whether a block is in camera view, and for determining bounding boxes

In addition, this version can draw double letter glyphs. No extra action is needed, you just supply "b6" as the label on a block and internally the code will detect it has to slightly modify the drawing procedure.

To actually get this functionality it is enough to just copy the new py files over the old versions, I forgot which ones exactly but if you copy app.py, camera.py, shapes.py, text.py, and util.py, I think that ought to do it.

------
Step 2. Generating new IDs and images

The ids are by default generated inside app.py when the image is generated. But we want them to be consistent across time steps. 
242 - 327 lines in "regenerate.py" are relevant for this, they have the procedure to generate consistent (2 glyph) ids and also show how to generate images with and without glyphs on them.

-------
Step 3. Generating visibility / bounding box information
See 274 - 375 especially 297 - 346
The main strategy is to use "dont_ignore_block" to generate an image containing a single block, then a mask is generated by considering all pixels below a threshold are 1 and the rest are 0. From this mask:
- visibility - the block is considered out of view if all mask pixels are black (the object was drawn outside of the field of view)
- bounding box - the bounding box is the left/right/top/bottom most pixel that is not 0 (see the get_bbox function)

This procedure has to be repeated for each block in the image to get it's bounding box and visibility info. However, the code in "heuristic.py" has an additional loop that goes over letter candidates (line 294). That loop is no longer necessary and makes everything much slower, so don't include it.

------
Step 4. Generating the xml/mmax files for annotation
I don't really know much about geneating this initially, but you can have a look at "apply_remapping.py" as it rewrites the relevant parts of the xmls (that were already generated elsewhere). Don't forget there are also some minor modifications to the xml schema (phrase_scheme.xml in the Common folder of the data, included in this repo aswell).

Basically the modification would be to use the bbox and visibility information for each block of an object from the previous steps to add the "objectFull" field, as it is added in "apply_remaping.py".
